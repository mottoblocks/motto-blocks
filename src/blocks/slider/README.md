# motto/slider

Part of the Slider family: `motto/slider` (this block, the carousel wrapper) contains one or more `motto/slide` (single slide) blocks — the same parent/child relationship as Accordion/Accordion Item. See `../slide/README.md` for the child block.

## Purpose

Carousel/slider block powered by Swiper.js. Wraps `motto/slide` children (`ALLOWED_BLOCKS = ["motto/slide"]`, `slider-constants.js`) inside a `.swiper > .swiper-wrapper` structure, with optional navigation arrows, pagination dots, scrollbar, and mouse wheel control. All Swiper configuration — slides-per-view, spacing, transition effect, autoplay, loop, mousewheel, navigation/pagination — is exposed as block attributes and serialized to `data-*` attributes for the frontend runtime to read.

## Attributes contract

Non-obvious fields only — see `block.json` for the full list and defaults.

- **`responsiveOptions`**: a per-breakpoint override object keyed by breakpoint id (from `@config/motto-breakpoints.json`), each holding a subset of `RESPONSIVE_KEYS` (`slidesPerView`, `slidesPerViewAuto`, `spaceBetween`, `navigation`, `pagination`). Read via `getResponsiveValue()`/`getSettings()` (`@components/slider/settings.js`), which fall back to the desktop-level attribute for any key not overridden at a given breakpoint. Written via `setResponsiveAttribute()` from the editor's device-mode toggle.
- **`swiperBreakpoints`** is not edited directly — it's derived from `responsiveOptions` by `buildSwiperBreakpoints()` and persisted into the attribute by a `useEffect` in `edit()` purely so `save()` has a ready-made Swiper breakpoints map without re-resolving the shared breakpoints config at render time. If it's empty/stale, `save()` recomputes it fresh via `buildSwiperBreakpoints(attributes, sharedBreakpointsConfig)` rather than trusting the persisted attribute blindly.
- **`navigationIcons`**: `{ prev, next }`, each `{ type: default|image|icon|svg, image: {id, url}, svg: {source, inline, lucideIcon} }`. Normalized through `normalizeNavigationIconOptions()` (`@components/slider/navigation-options.js`), which includes a legacy-migration branch mapping old `{ type: "svg", svg.source: "lucide" }` data onto the newer `"icon"` type.
- **`navigation`/`pagination`** (desktop-level) vs. `isEnabledInAnyMode()`: the nav-arrow and pagination-dot DOM elements are only rendered at all if enabled in *any* responsive mode, even if disabled at desktop — per-breakpoint enable/disable is then handled by Swiper's own `breakpoints` config, not by adding/removing DOM nodes.
- **`slidesPerViewAuto`**: when true, forces `settings.slidesPerView` to the string `"auto"` in `getSettings()`, overriding the numeric `slidesPerView` attribute entirely.
- **`mousewheelEnabled` + mousewheel option attributes**: when enabled, editor and frontend pass Swiper `mousewheel: { forceToAxis, releaseOnEdges, sensitivity }`. Defaults match the wheel-friendly page-scroll behavior: `forceToAxis: true`, `releaseOnEdges: true`, `sensitivity: 1`.
- **`transitionEffect`**: validated against `TRANSITION_EFFECT_VALUES` (`translate|fade|cube|coverflow|flip|cards|creative`) via `normalizeTransitionEffect()`; each value maps to a Swiper effect config in `getSwiperEffectConfig()` (`@components/slider/swiper-utils.js`) with hardcoded shadow/rotate/depth constants that aren't exposed as attributes.

## Behavior

- **Editor Swiper instance**: `useSwiperInstance()` (`use-swiper-instance.js`, wrapping the shared `@components/slider/use-swiper-instance.js`) mounts a real `Swiper()` inside the editor canvas via a `MutationObserver`-driven mount/update cycle. It force-remounts the whole instance (rather than just updating params) whenever `buildSwiperModuleSignature()` changes (effect, nav/pagination enabled, scrollbar, free mode) because Swiper's navigation/pagination modules keep internal state that a param update can't cleanly reset.
- **Editor selection interaction**: while an inner block (a slide's child) is selected, the Swiper instance is torn down entirely (`destroy(true, true)`) to keep Gutenberg's own block selection/editing stable. Clicking a slide itself (not its content) calls `swiper.slideTo()` and selects that slide's block (`onRootClick` in `use-swiper-instance.js`).
- **Frontend Swiper instance is a separate implementation**: `assets/js/slider-frontend.js` re-parses the same `data-*` attributes from scratch (`readSwiperConfigFromElement()`) and instantiates `window.Swiper` directly — it does not share code with the editor's `@components/slider/swiper-utils.js` at runtime; the logic is duplicated because the frontend script is a plain IIFE with no build step.
- **Cross-block registry**: `slider-frontend.js` registers every `.motto-swiper` element it initializes in a global `window.motto.sliders` map and fires `motto:slider:before-init` / `motto:slider:init` / `motto:slider:destroy` / `motto:slider:registry` `CustomEvent`s on `window`. `getSliderRootElement()` explicitly special-cases `.wp-block-motto-query-layout` as an alternate root — the Query Layout block in the `motto-dynamics` plugin reuses the same `.motto-swiper` markup/runtime, tagging the registry entry's `source` as `"motto/query-layout"` vs `"motto/slider"`.
- **Navigation icon SVG resolution differs by render path**: `NavigationIconMedia` (`@components/slider/navigation-icon-media.jsx`) renders `"image"`/`"icon"` (Lucide) icon types directly into `save()` output, but for the `"svg"` (custom inline SVG) type it returns `null` unless `isEditorPreview` is true — meaning the static `save()` markup ships an *empty* nav button for custom SVG icons. The actual sanitized SVG is injected server-side at render time by `motto_blocks_render_slider()` (`includes/helpers.php`), which regex-replaces the `<button class="swiper-button-prev|next">…</button>` markup using `motto_blocks_sanitize_svg()` on the stored `svg.inline` (or legacy `svg.raw`) value. This split exists because `save()` output is static, but sanitization needs to run on every render.

## Implementation notes

- **Frontend registration**: `motto_blocks_register_swiper_assets()` (`includes/assets-frontend-libs.php`) registers `assets/vendor/swiper/swiper-bundle.min.{js,css}` from the plugin's own bundled copy (no CDN — WordPress.org Plugin Check disallows offloading enqueued scripts/styles to a remote server), then registers `assets/js/slider-frontend.js` as `motto-blocks-slider-view` depending on the Swiper JS handle. `motto_blocks_register_slider_block()` (`motto-blocks.php`) wires `view_script_handles` to `motto-blocks-slider-view`, adds `motto-blocks-swiper-css` to both `style_handles`/`editor_style_handles`, and sets `render_callback` to `motto_blocks_render_slider()`.
- `motto_blocks_render_slider()` only runs its regex substitution when `motto_blocks_has_slider_navigation_enabled()` detects navigation is on in any mode (desktop attribute or any `responsiveOptions[mode].navigation`) — otherwise it returns the saved `$content` untouched.
- Shared editor logic lives in `src/components/slider/` (`settings.js`, `constants.js`, `swiper-utils.js`, `use-swiper-instance.js`, `navigation-options.js`, `navigation-icon-media.jsx`) and is imported by this block via the `@components` alias; `getSettings()`/`toDataAttributes()` (`settings.js`) are the single source of truth for turning attributes into both the editor's live Swiper config and the serialized `data-*` attributes `save()` writes.
- The frontend's `readSwiperConfigFromElement()` (`assets/js/slider-frontend.js`) is a hand-maintained parallel implementation of the same normalization/effect logic (`normalizeTransitionEffect`, `getSwiperEffectConfig`, breakpoint-module wiring) as `src/components/slider/settings.js` + `swiper-utils.js` — there is no shared module between the two.

## Known limitations

- Two fully independent Swiper config builders — editor (`src/components/slider/{settings,swiper-utils}.js`) and frontend (`assets/js/slider-frontend.js`) — with no shared source. A new Swiper option added to one must be manually ported to the other or editor/frontend behavior will diverge.
- `allowTouchMove: false` / `simulateTouch: false` are hardcoded in the editor's Swiper config (`use-swiper-instance.js`) to keep touch dragging from fighting the block editor's own selection/drag handling — touch/swipe gestures only work on the frontend instance, not in the editor preview.
- No `allowedBlocks` restriction beyond `ALLOWED_BLOCKS = ["motto/slide"]` at the wrapper `InnerBlocks` level; nothing prevents nesting another `motto/slider` inside a `motto/slide`.
- Custom inline SVG navigation icons depend on the `render_callback` running (dynamic rendering); if the block's markup were ever served through a path that bypasses `render_block()` (e.g. a raw `post_content` dump), custom SVG nav icons would render as empty buttons.
