# Feature Spec: SDD-015 — Motto AI v1
Version: 0.1
Status: Active
Owner: Architecture
Last Updated: 2026-07-12

> This spec documents `motto-ai` (`_dev/motto-ai/`) as it actually exists in code, written after auditing the implementation against the original proposal in `SDD-006` (now `Superseded`). It replaces SDD-006 as the reference for current behavior.

## 1. Goal
Provide a Gutenberg sidebar panel where users describe layouts (or edits to selected blocks) in natural language, and receive fully-formed `motto/*` block trees — including complete `mottoStyler` attributes — generated by an AI provider through a secure PHP proxy.

## 2. Scope

In scope (current implementation):
- Sidebar panel (`PluginSidebar`, not a toolbar modal) registered as `motto-ai`.
- Two modes: **Generate** (insert new blocks at the current position) and **Modify** (replace the currently selected block(s) with an AI-edited version) — mode toggle only appears when a block is selected.
- Voice input via the Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`), hardcoded to `es-ES` locale, appends transcript to the prompt textarea.
- Dynamic block catalog: `GET /motto-ai/v1/catalog` scans `block.json` files under `motto-blocks` and `motto-dynamics` build directories for a `mottoAI` field, and infers `acceptedChildren` from `parent` declarations across all scanned blocks.
- Secure PHP proxy: `POST /motto-ai/v1/generate` — API key never reaches the browser.
- Two providers: Anthropic (`claude-opus-4-7`, Messages API) and OpenAI (`gpt-4o`, Chat Completions).
- Full `mottoStyler` attribute generation (css per breakpoint, `blockSelectors`), not just inline style props.
- Admin settings tab (`Settings → Motto AI`) hooked into the shared `motto_blocks_admin_tabs` filter; API key stored via `motto-blocks`' shared masked-secret helpers (`motto_styler_get_masked_secret_placeholder`, `motto_styler_update_secret_option_from_post`) when available, with a plain fallback.

Out of scope (not implemented, despite being proposed in the superseded SDD-006):
- Summary/confirm step before insertion — the current flow inserts/replaces immediately on a successful response.
- Multi-turn clarifying questions (`clarifications` field) — the REST response is `{ blocks: [...] }` only.
- Client-side validation of AI-returned block names before `createBlock()` — see Risks.
- Encryption of the stored API key (masked display only, same posture as other Motto secret options).
- Configurable voice-input locale (currently hardcoded `es-ES`).
- Automated test coverage — none exists for this plugin as of this spec.

## 3. Current Behavior
Prior to `motto-ai`, no AI-assisted generation existed for the Motto ecosystem; `SDD-006` proposed a plugin (`motto-agents`) with a hardcoded 6-pattern catalog and a summary/confirm UX flow. That plugin was never built under that name or contract — `motto-ai` was built instead, with a different (dynamic, catalog-driven) architecture and a more direct UX. See `SDD-006`'s superseded note for the itemized divergence.

## 4. Target Behavior
1. User opens the "Motto AI" sidebar in the block editor.
2. If a block is selected, a "Modify selected" toggle appears. Off → Generate mode (insert new blocks at the current position). On → Modify mode (replace the selected block(s)).
3. User types a prompt (or dictates via the mic button, appended to any existing text) and clicks Generate/Modify.
4. Client calls `POST /motto-ai/v1/generate` with `{ prompt }` (Generate) or `{ prompt, currentBlocks }` (Modify, where `currentBlocks` is the serialized selected block tree).
5. Server fetches the dynamic catalog (`GET /motto-ai/v1/catalog`, internal `rest_do_request`), builds a system prompt embedding the catalog JSON plus fixed rules (see §5), and dispatches to the configured provider (Anthropic or OpenAI).
6. Provider response text is stripped of markdown code fences, `json_decode`'d into a block descriptor array; malformed JSON returns a `400`/`500` `WP_Error` (`invalid_json`), not a fatal.
7. On success, the client recursively converts descriptors to real blocks via `wp.blocks.createBlock()` and either `insertBlocks()` (Generate) or `replaceBlocks()` (Modify) into `core/block-editor`.
8. No confirmation step: a successful response is applied immediately. Undo relies entirely on Gutenberg's native history.
9. Missing API key: the provider dispatcher returns a `400` `WP_Error` (`no_api_key`) before any external call is made; the client surfaces it as a dismissible `Notice`.

## 5. Data Contract

- Inputs:
  - REST `POST /motto-ai/v1/generate`: `{ prompt: string (required, sanitized), currentBlocks?: BlockDescriptor[] }`. Auth: `edit_posts` capability.
  - REST `GET /motto-ai/v1/catalog`: no params. Auth: `edit_posts`. Returns array of `block.json` entries (from `motto-blocks` + `motto-dynamics` build dirs) that declare a `mottoAI` field, each augmented with an inferred `acceptedChildren` array.
  - WP options: `motto_ai_provider` (`anthropic` | `openai`, default `anthropic`), `motto_ai_api_key` (masked on display, plaintext at rest — same posture as other Motto secret options).
  - `BlockDescriptor`: `{ name: string, attributes: object, innerBlocks: BlockDescriptor[] }`.
  - `mottoStyler` shape expected from the model (per system prompt): `{ instanceId, css: { desktop, tablet, landscapePhone, phone }, blockSelectors: [{ selector, label, css }] }` — `id`/`selectorType` on `blockSelectors` entries are omitted by design (generated at runtime, per `docs/conventions/architecture.md`).
- Persistence:
  - No per-post or per-block persistence beyond the inserted/replaced blocks themselves (standard Gutenberg attribute persistence).
  - Settings persisted in `wp_options` as above.
- Outputs:
  - REST response: `{ blocks: BlockDescriptor[] }` on success; `WP_Error` (`no_api_key` 400, `invalid_json` 500, `anthropic_error`/`openai_error`/`unknown_provider`) on failure.
  - Editor: new or replaced blocks in the canvas; error `Notice` on failure.

## 6. Acceptance Criteria
- [x] User can open the Motto AI sidebar and submit a prompt without leaving the editor.
- [x] A valid prompt inserts a `motto/*` block tree that passes Gutenberg validation.
- [x] Generated blocks carry complete `mottoStyler` attributes (not just inline style props).
- [x] API key never appears in any JS bundle or REST response body (server-side only, `wp_remote_post` from PHP).
- [x] Submitting with no API key configured returns a structured error surfaced in the UI (no PHP fatal).
- [x] Provider API failures return a structured `WP_Error`, not an uncaught exception/500 without message.
- [x] Selecting a block and toggling "Modify selected" sends `currentBlocks` and replaces the selection instead of inserting.
- [x] Voice input transcribes and appends to the existing prompt text.
- [ ] Unknown/unregistered block names returned by the AI are rejected before `createBlock()` is called. — **Not implemented**: `buildBlocks()` calls `wp.blocks.createBlock()` directly with no `wp.blocks.getBlockType(name)` guard. Carried over as an open gap from SDD-006's original acceptance criterion.
- [ ] Automated test coverage for the block-tree conversion and PHP proxy. — **Not implemented**: no test files exist for this plugin.

## 7. Risks and Mitigations
- Risk: AI returns an unregistered block name; `createBlock()` behavior for unknown names is untested here (Gutenberg typically falls back to a "missing block" placeholder, but this is not verified for this codebase).
  - Mitigation: add a `wp.blocks.getBlockType(name)` check in `buildBlocks()` before insertion, skipping and reporting unregistered names — not yet implemented.
- Risk: no confirm/summary step — a bad generation is applied directly to the canvas (worse for Modify mode, which replaces existing content).
  - Mitigation: relies entirely on Gutenberg's native undo (`Ctrl/Cmd+Z`); no additional safety net exists.
- Risk: `wp.remote_post` calls to Anthropic/OpenAI have no explicit retry or rate-limit handling; a transient provider error surfaces directly to the editor.
  - Mitigation: none beyond the existing structured `WP_Error` passthrough.
- Risk: API key stored in plaintext at rest (masked only for display), same posture as other Motto secret options — documented, not a regression specific to this plugin.
- Risk: voice input is hardcoded to `es-ES`; non-Spanish-speaking users get no working voice input (Web Speech API will still "work" but misrecognize).
  - Mitigation: none yet; candidate for a locale setting in a future phase.
- Risk: zero automated test coverage — regressions in prompt construction, catalog scanning, or block-tree conversion would only surface manually.

## 8. Test Plan
Automated:
- None exist today. Candidates for future coverage: catalog-scanning `acceptedChildren` inference, markdown-fence stripping + JSON parsing of provider responses, `buildBlocks()`/`serializeBlock()` round-trip.

Manual:
- Generate mode: submit a layout prompt, confirm valid `motto/*` blocks with populated `mottoStyler` insert without validation warnings.
- Modify mode: select an existing block, toggle "Modify selected," submit an edit instruction, confirm `replaceBlocks` swaps only the selection.
- Submit with no API key configured: confirm the `Notice` error, no PHP fatal.
- Voice input: dictate a prompt, confirm transcript appends correctly to existing text.
- Force a malformed provider response (e.g. temporarily break the system prompt): confirm `invalid_json` error surfaces cleanly.

## 9. Rollout Plan
Phase A (shipped): sidebar panel, dynamic catalog, Generate + Modify modes, Anthropic/OpenAI providers, voice input, admin settings tab.

Phase B (candidates, not scheduled):
- Block-name validation before insertion (close the acceptance-criteria gap in §6).
- Automated test coverage (PHP proxy + JS block-tree conversion).
- Configurable voice-input locale.
- Optional confirm/preview step before insert/replace (would partially reintroduce SDD-006's original UX, as an opt-in safety net rather than a mandatory step).

Rollback:
- `motto-ai` is an independent plugin (`Requires Plugins: motto-blocks`); deactivating it removes the sidebar panel and REST routes with no data loss to existing post content (inserted blocks remain standard Gutenberg blocks).
