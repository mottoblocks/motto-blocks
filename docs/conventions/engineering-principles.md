# Engineering principles

Use when choosing between approaches **not** already specified in `docs/conventions/*` or established repo patterns. Those docs win; these principles only fill the gaps.

- **Prefer durable structure over quick patches.** Invest a bit more up front if it removes a category of future bugs or refactors.
- **Conventions are part of the product.** Naming, layout, and written rules reduce cognitive load for humans and agents alike — treat them as assets, not ceremony.
- **Test hypotheses like code.** State assumptions, check them against the codebase and constraints, and compare trade-offs explicitly.

Does not override `docs/conventions/*`.
